**结论**：B5 的七项在**客户端侧**基本都真落地了，而且落得比 r1 建议更细：计算样式/盒子可见性（含 jsdom 退化 + withLayout 桩覆盖真实分支）、W3C accname 阶梯、ref 跨 collect 对元素黏附（WeakMap + 全局单调 seq）、配额分级（浮层→视口内→其余→静态单元格）与 elementsTruncated/elementsOmitted 如实标注、open shadow root 穿透、块级边界正文 + 多候选根公共祖先、DOM 静默窗（有 1500ms 绝对上限、无 body/无 MutationObserver 即刻放行）。13 条里 6 条 closed、1 条 not-applicable。

但有一个贯穿性的问题：**多条修复只做到「客户端如实上报」，没走完到「服务端/模型真的看得见」这一步**。最典型的是 A-PAGE-02——elementsTruncated/elementsOmitted 从 collect 到帧到 schema 全链路都有了、单测也断言了，可 `apps/server/src` 全仓 grep 这两个字段**零命中**，gateway.ts:2453-2466 的 reportBody 只对 text 附 note，模型拿到的 JSON 里根本没有截断信号；该发现的原始危害「agent 把没采到当成不存在」一字未减。A-PAGE-04 同理：黏附 ref 确实杜绝了「旧 ref 改绑到别的控件」这个最严重形态，但裁定里的另一半（snapshotEpoch 被服务端消费、复核/watch 快照同步 domContext）一行没写，schema:843-847 的 $comment 却已经把「服务端据此判定是否已过期」当既成事实写进了契约。A-PAGE-11 只有压缩路径（新 redactForLlm）脱敏，主回合喂给模型的 reportBody.url 仍是原始全量 URL。
