# adr-023: 任务组多 tab 工作区——agent 的组级视野与定向操作

## 状态

已接受（2026-08-10）。D0-D3 全部实施，各期落地状态见「分期落地」表。

## 目标与范围

会话已是组级共享（adr-012/013：一个 tab 组一个会话），但 agent 对这个组是「盲」的：
它不知道组里开着哪些页、不能对非活跃页做任何观察或操作。本 ADR 给 agent 补上两件事：

1. **组级视野**：组内页面清单作为渐进披露的会话层注入，agent 知道工作区里有哪些页、
   各页在哪个站点、处于什么状态；
2. **定向操作**：工具调用可显式指定目标页，观察与副作用不再被迫绑死「用户视线所在的活跃页」。

范围内：清单注入形态与 token 成本、定向标识的契约表达、exec 路由从活跃页单播扩展为
目标页单播、HITL 卡与审计事件的目标页标注、站点边界标记的多 tab 化、与本轮 P1 静默页
直执行通道的衔接。

范围外：跨窗口/多会话并行（adr-012 锚点不动）、多页并行执行（见「风险与权衡」被否方案）、
pack 间工具白名单的跨页合并（见「总体架构」§4 的边界，挂锚点）。

## 背景与约束

现状事实（已核实）：

- **会话已组级共享**：一个 tab 组一个会话桥、一条 SSE；面板叙事帧（text-delta / tool-card /
  hitl-request 等）全员镜像；组内换站历史延续，站点边界标记防历史误导（adr-013 §3/§5）。
- **装配按活跃页逐消息解析**：context-report 以活跃页为准，逐回合按活跃页 URL 解析
  packId/featureId 并全量重组注入。
- **带副作用帧只投活跃页**：`group-routing.ts` 把 exec-instruction / guide-action /
  snapshot-request 单播给活跃页成员；无显式活跃者回退到「仍在组内且曾活跃过」的最近成员，
  再无则不投递（fail-safe）。这条路由**从结构上排除**同一签名指令被多页重复执行。
- **agent 无组内 tab 清单**：渐进披露现有两层——「已安装站点索引」（静态，列全部带 site 的
  pack，回答「可以去哪」）与 pack docs 索引；没有「现在开着哪些页」这一层。agent 既看不见
  组内非活跃页，也无法定向操作它们。
- **本轮 navigate 演进**（背景事实，非本 ADR 决策）：P0 组内同源 tab 复用（navigate 优先复用
  组内已有同源 tab 而非新开）；P1 静默页 background 直执行单步 navigate（对从未活跃、无
  content script 交互保证的组内页，由插件 background 经 tabs API 直接完成导航这一种步）。

约束（边界铁律，全部沿用不放松）：

- 决策永远服务端 fail-closed（U7）：分级/HITL 判定不下放客户端，代执行指令一次性签名
  （nonce+ttl），结果过 resultSchema 校验才回喂。
- 装配治理对对话内容免疫（U8）：清单是数据不是指令，不得成为改变治理注入的旁路。
- 审计永远旁路 record-only（U6）：目标页标注是事件字段扩展，不进控制流。
- 形态差异不外泄进契约（U5）：adr-012 曾据此否决「tabId 进契约/服务端路由」——本 ADR
  必须在不违背该裁决精神的前提下表达定向（见「风险与权衡」第一条）。

宗旨自证：组级视野让 agent 准确知道用户工作区的真实构成，不再对「另一个 tab 里已经开着
目标页」视而不见（准确性）；定向操作让「读后台页内容、在后台页导航」这类真实诉求不必先
打断用户视线切页（辅助自由度），且全部定向仍走服务端裁决与一次性签名（治理边界不动）。

## 总体架构

### 1. 组内页面清单：渐进披露的会话层（第二层）

渐进披露分层定型为三层，各答一问：

| 层 | 回答 | 数据源 | 稳定性 |
|---|---|---|---|
| 已安装站点索引（现有） | 「可以去哪」 | L1 快照（全部带 site 的 pack） | 跨会话静态，随快照版本变 |
| **组内页面清单（本 ADR）** | 「现在开着哪」 | 会话组成员状态（插件上报） | 会话内动态，随开关页/导航变 |
| pack docs 索引（现有） | 「细节去哪查」 | 激活 pack 的 docs/ | pack 级静态 |

清单形态：每页一行——`句柄 | 标题（截断）| URL（截断至 origin+path）| 状态 | 激活 pack`。
状态取 `active`（活跃页）/`background`（曾活跃、content script 在场）/`silent`（入组但从未
活跃，无 content script 交互保证——即 group-routing fail-safe 排除的那类页）。

token 成本控制：

- **注入门槛**：组内 ≥2 页才注入；单页时清单只有活跃页自身，无信息量，一行都不花。
  （与站点索引「<2 site 不注入」同一手法。）
- **行级上限**：标题/URL 截断；清单页数设上限（建议 20），超限截断并注明「另有 N 页」。
  清单只含元数据，不含任何页面正文/快照——内容按需经定向 `page_snapshot` 取（正文走其
  `includeText` 分支）。
- **注入位置**：置于系统注入尾部（基座、站点索引、功能块之后）。基座与站点索引是 prompt
  缓存前缀，清单是会话内最易变的段，放尾部使前缀命中不受清单变化影响。

清单与站点索引的层级关系：索引是能力面（装了哪些 pack、各自入口 URL），清单是工作区
现场（这些能力面上现在开着哪些实例页）。两层各自独立注入、互不内联：清单行的「激活
pack」列只引 packId，不重复索引里的用途描述。

### 2. 定向标识：会话页面句柄，不是 Chrome tabId

- 插件 background 为每个入组成员生成**会话作用域的不透明页面句柄**（如 `p1`/`p2`，会话内
  单调递增），只经上行 `group-pages` 清单帧全量携带（服务端每帧整体重建状态表）；
  context-report 等其余上行帧不带句柄。句柄 ↔ Chrome tabId 的映射封装在插件内部，
  tabId 永不出现在契约与服务端。
- 句柄语义是「本会话工作区内的一个页面实例」——嵌入 SDK 的多 iframe、浏览器壳的多视图
  同样能实现这一语义，故句柄是形态中立的接入层概念，不触犯 U5（详细论证见「风险与权衡」）。
- 工具入参增加可选 `targetPage` 字段（取值 = 清单句柄）；**缺省即活跃页**，现有全部行为不变
  （additive，不破坏既有 pack 与评测）。该字段由平台统一增广：toolgate 载入期给 dom 工具的
  params schema 加可选 `targetPage`（bounded-fulfillment 工具不增广），内建 navigate 的结构契约自带，
  **pack 制品（tools.json）零改动**；`targetPage` 因此是平台保留参数——pack dom 工具自声明它即语义
  劫持，载入期 fail-fast 拒启；其余参数名（含 `page`）pack 自由使用。入参保留名与下行帧、审计
  事件的落点字段名 `page`（§4/§5）分属两层命名面，各自独立。

### 3. 服务端裁决与签发：围栏按目标页计算，fail-closed 不动

服务端（gateway/toolgate）维护组页面状态表：由成员 context-report 与清单上报驱动，
记录每个句柄的 URL 与状态。裁决链新增「目标页解析」一步，其余不变：

- 调用带 `targetPage` → 以状态表中该句柄的 URL 作为围栏与装配判定的基准 URL：dom 工具的
  site 围栏（origin+path，adr-013 §5）按**目标页 URL** 校验；句柄不在状态表、状态表 URL
  越出签发工具所属 pack 的围栏，一律拒签。
- 调用不带 `targetPage` → 一切按活跃页，与现状完全一致。
- 分级矩阵/HITL 判定、一次性签名（nonce+ttl+Ed25519 覆盖落点 `targetPage` 与完整 request）、
  结果 resultSchema 校验——全部不变。定向只改「副作用落在哪一页」，不改「谁批准副作用」。

**工具白名单仍按活跃页装配，定向不扩白名单**。这是本 ADR 刻意保持的边界：每回合可用
工具集依旧由活跃页的 pack 投影，定向只改变已获准工具的执行落点。配合「围栏按目标页
校验」，自然推出干净的不变量——

- pack 工具（dom/http）只能定向到**落在本 pack site 围栏内**的组内页（同站多 tab 场景）；
- 平台内建工具（`page_snapshot`，含其 `includeText` 正文分支 / navigate 类）跨功能稳定、无 pack 围栏差异，
  可定向组内任意页；
- 「用 B 站 pack 的工具操作 B 站后台页」在 A 站活跃时不可达——那要求跨页合并白名单，
  复杂度答不上宗旨基准，维持经 navigate/用户切页改变活跃页的既有通路（锚点：出现「不切
  活跃页就必须动用他站 pack 工具」的真实场景时再评估）。

### 4. exec 路由：活跃页单播 → 目标页单播

`group-routing` 的 `active-page` 路由扩展为 `target-page`：

- 下行帧（exec-instruction / guide-action / snapshot-request）增加可选目标句柄；有句柄按
  句柄单播，无句柄回落现活跃页语义（含 fail-safe 回退链）。guide-action 的目标句柄为预留
  字段：服务端不填充，引导恒落活跃页（接线锚点见「锚点登记」）。
- **防重复执行不变量逐字保持**：单桥单 SSE + 每帧至多投递一个成员，结构上仍不存在同一
  签名指令到达多页的路径；nonce 一次性核销继续作为纵深兜底。
- **定向失败 fail-safe，禁静默改投**：目标句柄成员已离组/断连 → 不投递，超时后如实回喂
  执行失败；绝不回退到活跃页——带副作用的帧落错页比不落更糟。
- **定向单步 navigate 的落点由签名帧句柄钉死**：该形态一律由插件 background 对句柄解析出的
  那一个 tab 直执行，不论目标成员有无 content 端口——经 content 委托会走组内同源复用判定
  （排除发起页、可改投同源他页并夺焦），与「用户批准的目标页 = 被导航的那一页」相悖。
  其余帧形状不进直执行面（形状不获准即丢帧）。

### 5. HITL 卡、审计与站点边界标记的多 tab 化

- **HITL 卡标注目标页**：卡片（panel 路由，全员镜像）呈现目标页的标题+origin（缺省时即
  活跃页），用户裁决时明确知道副作用会落在哪一页。定向到非活跃页的副作用操作，HITL 文案
  显式区别于「当前页面」措辞。
- **审计事件补目标页字段**：C5 事件扩展 `{page: {handle, origin}}`（additive；schema 独立
  于落点，U6 不动）；exec 签发、执行结果、HITL 裁决三类事件同步携带，审计流可回答
  「这次操作落在组内哪一页」。
- **边界标记语义细化**：现「以下对话发生在 X 站点」按活跃页 origin 变更注入历史。多 tab
  定向后，该标记语义收窄为「活跃页所在站点」；**定向操作不触发边界标记**（它不改变活跃
  页），代之以**观测级页标注**——定向快照的观测回喂前缀标注来源页（如
  `[来自 p3 · https://mail.126.com]`，origin 不可解析时退化为 `[来自 p3]`），防止 agent 把
  后台页内容误当活跃页状态；定向代执行的结果 observation 不加标注（落点已由同轮 tool_call
  回声里的 `targetPage` 实参自明，且结果本身不是页面内容）。标注独占观测首行；P1 历史压缩的摘要保留集（compress.ts 已保留
  边界标记）与 P0 快照瘦身存根同步保留该标注行。

### 6. 与本轮 P0/P1 navigate 演进的衔接

- **P0 同源 tab 复用**：清单正是复用判定的显性化——服务端与 agent 都看得见「组内已有
  同源页」。清单就位后，复用从插件内隐式行为升级为 agent 可显式表达的意图
  （navigate 带 `targetPage` 定向 = 「在那一页上导航」，而非新开）。
- **P1 静默页直执行**：静默页无 content script 交互保证，故按**通道分级**衔接定向：
  - `active`/`background` 页：全部 dom 步可执行（content script 在场）；
  - `silent` 页：仅 background 可直执行的步（本轮即单步 navigate）可获签发——此为 pack dom
    工具口径；内建 site_navigate / open_url 对任意组内页（含 silent）恒可定向，导航即其激活通路；
  - toolgate 按状态表中目标页状态在**签发前**判定：对 silent 页定向 dom 操作 → 拒签并如实
    回喂「目标页不可交互，需先导航激活」，不静默降级、不隐式唤起。
  状态分级由此成为裁决输入的一部分——这也是清单必须含状态列的原因。

### 契约要点（规范性）

- 工具调用的 `targetPage` 字段 MUST 为可选；缺省语义 MUST 等价于现活跃页行为。
- 服务端 MUST 以自身维护的组页面状态表解析句柄；句柄未命中、URL 越围栏、通道/状态不满足，
  MUST 拒签（fail-closed），MUST NOT 回退到活跃页执行。
- 下行副作用帧 MUST 保持单成员投递；目标成员不可达时 MUST NOT 改投其他成员。
- 页面句柄 MUST 为会话作用域不透明标识；Chrome tabId 及其他形态特有标识 MUST NOT 进入
  契约、服务端状态与审计事件。
- 审计目标页字段 MUST 为 additive 扩展；旧事件消费方 MAY 忽略之。
- 清单注入 MUST 逐回合全量重建、随治理注入走结构化通道；对话内容 MUST NOT 能改写清单
  （清单只源于成员上报，U8）。
- 清单 SHOULD 在组内 ≥2 页时才注入；行数 SHOULD 设上限并截断注明。

## 关键流程

**流程 A：组级视野（只读）**
用户在 A 站活跃页提问「邮箱那个 tab 里验证码是多少」→ 装配按活跃页注入 A 站 pack +
清单（含 `p3 | 126邮箱 | mail.126.com/... | background`）→ agent 定向
`page_snapshot(targetPage=p3)` → toolgate：内建工具、句柄命中、按矩阵放行 → 帧带目标句柄单播
p3 → 快照结果带 `[来自 p3]` 页标注回喂 → agent 作答。全程活跃页不动、用户视线不被打断。

**流程 B：定向副作用（同围栏多 tab）**
同站开两个工单页，用户令 agent 在后台那页提交表单 → agent 以活跃页 pack 的 dom 工具
定向 `targetPage=p2` → toolgate 按 p2 的 URL 校验 pack site 围栏（命中）→ HITL 卡标注
「目标页：工单 #4521（同站后台页）」→ 用户批准 → 一次性签名指令单播 p2 执行 →
结果过 resultSchema 回喂，审计事件带 `{page:{handle:'p2',origin:...}}`。

**流程 C：静默页定向的拒签与引导**
agent 对 silent 页 p4 定向点击操作 → toolgate 读状态表：p4=silent，dom 步不可执行 →
拒签，回喂「p4 不可交互，可先 navigate 激活」→ agent 改为对 p4 签发单步 navigate
（silent 页准入通道，P1 background 直执行）→ 页面载入、用户切过去后 p4 转 active，
后续操作走流程 B。

**流程 D：定向失败不改道**
签发后目标页被用户关闭 → 帧无成员可投 → 不投递，超时如实回喂失败 → 下一回合清单已
不含该句柄，agent 与用户基于真实状态重新决策。任何环节都不发生「换一页替它执行」。

## 风险与权衡

- **U5 张力：句柄 vs adr-012 对 tabId 的否决**。adr-012 否决的是「Chrome tabId 进契约/
  服务端路由」——那是把插件形态的原生标识外泄进契约。本 ADR 引入的是「会话工作区页面
  实例」这一接入层概念：三形态都能实现（插件映射到 tab、SDK 映射到 iframe/视图、浏览器壳
  映射到自有页对象），映射封装在形态内部。判据是「换一种形态，契约字段是否仍有自然语义」
  ——句柄有，tabId 没有。风险在于实现时的纪律滑坡（图省事直接把 tabId 当句柄传），须以
  契约测试钉死句柄的不透明性（服务端不得解析句柄结构）。
- **保留入参占用 pack 的参数名空间**。平台一旦保留某个入参名，全体 dom 工具的该名字即被
  定向语义占据，pack 用同名业务参数会被定向解析劫持，只能靠载入期 fail-fast 拒启暴露；而
  `page` 正是站点工具最自然的分页参数名（列表类工具的页码），保留它等于向全生态收一笔命名税。
  故保留名取 `targetPage`：语义直述「落点页」，与业务语域几乎不相交，保留面收敛为唯一一个
  名字，`page` 归还 pack 自由使用。下行帧与审计事件的落点字段不进 pack 声明面，故沿用 `page`
  不构成冲突。残余风险是保留名仍是全局约定，冲突只在载入期而非编写期可见——拒启报错点名
  该保留名，使冲突可自解释。
- **清单/状态表源于客户端上报的信任边界**。围栏按上报 URL 计算，理论上恶意客户端可谎报
  URL 骗过围栏。这与现状 context-report 驱动装配是**同一信任级**，定向不扩大信任面：
  执行发生在同一客户端的用户浏览器里，谎报者只能骗自己的执行环境；服务端继续不采信执行
  结果原文（resultSchema 校验）、决策全部 fail-closed（U7 的「不采信客户端上报原文」指
  治理判定不依赖客户端自称的执行结论，而围栏基准 URL 本就来自客户端环境声明）。真正要
  防的是「A 用户指挥 B 用户的页」，而组/会话/身份的绑定已结构性排除之。
- **上传数据面从活跃页扩到全组页面**。此前进入 prompt / 会话落盘 / 审计的页面地址只有活跃页
  一处；清单就位后，组内每一页的标题与地址都进这些通道，且三处口径不同：注入侧逐回合给出
  「标题（截 40）| URL（截至 origin+path 再截 80）| 状态 | 激活 pack」，不含 query/fragment、
  不含任何页面正文；服务端组页面状态表按上报原样持有 URL（含 query/fragment），启用会话
  持久化时随 `group-pages` 事件落 `.za/sessions/<id>.jsonl`（闲置 TTL 到期连内存项与文件一并
  逐出），该原样 URL 不进模型上下文；审计事件 `page` 只记 `{handle, origin}`，无 path/query。
  缓解：≥2 页注入门槛、页数上限（20 行）与行级截断、URL 列截至 origin+path、清单只含元数据。
  残余风险两条：一是 origin+path 保留 path 本身，后台页路径可能自带敏感信息（工单号、文档名、
  收件人标识），它逐回合进模型上下文；二是用户可能未意识到非活跃页的标题与地址也在被上报，
  「视线所在页」不再等于数据面边界。按用户配置排除指定 origin 的缓解挂锚点（见「锚点登记」），
  本 ADR 不实现。
- **token 成本与 prompt 缓存**。清单逐回合重建且随导航变化，放注入尾部保护基座+索引的
  缓存前缀；≥2 页门槛 + 行截断 + 页数上限把最坏情况钉在可控常数。残余风险是大组（几十页）
  下清单仍显著占用上下文——页数上限截断兜底，「清单退化为可查询工具」挂锚点（组规模
  常态性超过上限时评估）。
- **HITL 认知负担**。目标页标注让裁决多一个须阅读的维度；不标注则更糟（用户以为操作
  落在眼前页）。缓解：缺省（活跃页）时不加额外措辞，仅定向非活跃页时显式标注。
- **状态表新鲜度**。页在签发与执行之间导航走样 → 围栏校验时的 URL 与执行时不一致。
  既有防线已覆盖：ttl 收窄时间窗、执行侧 content script 在副作用前的就地校验、结果
  resultSchema 校验；此风险与现活跃页路径同构，不因定向而新增。

### 被否方案

- **Chrome tabId 直接进契约**：形态标识外泄，违 U5；adr-012 已否，本 ADR 不重开。
- **`list_tabs` 查询工具替代清单注入**：按需取、零常驻成本，但定向是高频前置知识，每次
  多一轮工具往返；清单本身极小（行级元数据）。注入为主、查询挂锚点（大组场景）。
- **多页并行/广播执行**：把 exec 帧投多个成员可「提效」，但直接摧毁「同一签名指令至多
  到达一页」的结构不变量，重复副作用防线从结构保证退化为 nonce 兜底。否。
- **每 tab 独立子会话 + 联邦协调**：adr-013 已否会话联邦（跨会话状态同步 + 多 agent loop
  一致性是新复杂面）；组级共享会话正是为避开它。
- **定向时按目标页 pack 重投影工具白名单**：让「A 站活跃时用 B 站工具操作 B 站后台页」
  可达，但一回合内多 pack 白名单并存 = 跨站干扰卷土重来（adr-013 拒绝的正是这个），
  且 HITL 语境（用户看着 A 站批 B 站操作）显著劣化。维持「白名单随活跃页、定向不扩权」。
