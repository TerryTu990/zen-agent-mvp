# adr-025: 基座通用化——从「配置未覆盖即拒答」到「事实边界 + 通用助手」

## 状态

已接受（2026-09-03，Terry 就 §决策待定项四条一并裁决，见 `../plans/2026-09-03-terry-rulings-and-next-round.md` R-1）。
**本 ADR 起初是对既成事实的补记**：
生产基座已于 2026-09-03 由 commit `470d3a9` 改为通用助手形态，「拒答边界」评测维度随之退出。
r1 审核（A-UX-01 / A-DOC-01 / A-ASM-04，三条均经三票验证存活）指出该定位级变更**没有任何 ADR 记录**，
且产品规则 R8 与 SSOT §1 仍以 MUST 要求拒答——两套口径并存且互相矛盾。
本文补上决策记录与其影响面清单；R8 与 SSOT §1 的规范性改写属定位级，**已由 Terry 裁决采纳**（见 §决策待定项）。

## 背景

R8（`docs/plans/2026-08-04-product-form-definition.md` §3）原文要求：
「配置未覆盖的问题 MUST 明确拒答并指引安装对应 pack，不猜测」。
它与 SSOT §1 信任阶梯第 1 档「基于 pack 事实的有据回答，配置未覆盖明确拒答」互为表里，
并支撑了评测的「拒答边界」维度与 UI 规范里的拒答气泡形态。

`470d3a9` 之后的生产事实：

- `assets/system-prompt.md` 的开篇定位改为「你是用户浏览器里的通用助手：回答问题、写作与翻译…」；
  原 ZA-SYS-02「辅助范围默认从严、无关一律拒答」整段删除。
- 评测的 refusal 维度整体退出；`assets/packs/generic-web/eval/scenarios.json` 的 `generic-general-qa`
  反向断言：站点页面上的通用问题**直接应答**，且 `mustNotMention` 含「职责范围」。
- 默认 E2E 门 `run-m1.mjs` 的场景 e 断言「职责范围/无关」因此**在基线即红**（本轮 B2 已改正为断言通用问答哨兵）。

即：产品已经从「站点助手，越界即拒」换轨为「通用助手 + 站点知识增强」。

## 决策（对既成事实的追认）

**D1 通用问题直接应答。** 与当前站点无关的通用请求（写作、翻译、常识问答）直接回答，不再以「职责范围」为由拒绝。
理由：用户在任意站点上打开侧栏时，「这个助手只肯谈本站」是反直觉的产品体感；
且竞品（chatGPTBox / Sider / Monica 等侧栏助手）全部是通用助手形态，「只谈本站」构成安装门槛而非差异化。

**D2 拒答不再是能力档的定义，事实边界才是。** 讲解档的治理承诺从「未覆盖即拒答」收窄为
「**站点功能的陈述**以 pack 事实与页面证据为准，未覆盖时如实说明未能确认，不臆造站点行为」（对应基座 ZA-SYS-04）。
区别在于：拒绝回答**整个问题** vs 拒绝**臆造站点事实**。后者才是「有据讲解」真正要守的东西，
前者在通用助手形态下既做不到也不该做。

**D3 评测维度闭集随之调整。** 「拒答边界」维度退出，其判据并入「讲解正确」；
闭集现为：讲解正确 / 装配换出 / 引导命中 / 工具触发 / HITL 触发 / 自动化触发
（本轮 B1 已同步 `.claude/rules/ZA-EVAL.md` 与 `CLAUDE.md`）。

## 决策待定项（已由 Terry 于 2026-09-03 裁决，改写落在下一轮 N1 批次）

1. **R8 的规范性改写**：`docs/plans/2026-08-04-product-form-definition.md` §3 的 R8 仍是 MUST 拒答。
   建议改写为「**R8 事实边界**：站点功能的陈述 MUST 以 pack 事实与页面证据为准；
   未覆盖时 MUST 如实说明未能确认、MUST NOT 臆造站点行为；与站点无关的通用请求不受此限」。
   落地：本批（N1）已按该措辞改写 R8 与 §2.1 信任阶梯表、§4 表面表、§5 通用性矩阵。
2. **SSOT §1 信任阶梯第 1 档**的措辞同步（现文仍写「配置未覆盖明确拒答」）。
   落地：本批（N1）已改为「配置未覆盖如实说明未能确认」，§10 待裁决登记同步转为已裁决。
3. **UI 规范** `docs/design/ui-style-guide.md` §5/§7 的拒答气泡形态与固定措辞是否保留
   （若 D2 成立，它应改为「事实边界提示」而非「拒答」）。
   落地：本批（N1）已把 §5 气泡形态定为「事实边界提示」并删去待裁决括注，措辞以 §7 术语表为准。
4. `assets/system-prompt.md` 的 ZA-SYS-04 与 ZA-SYS-01 在 generic 页面上的张力（r1 A-ASM-06）：
   前者要求「站点功能未覆盖即明确不确认」，后者定位为通用助手——
   在 GitHub、邮箱这类公知站点上，用户问「这里怎么 fork」时基座当前要求拒答，与评测 `generic-general-qa` 的方向相反。
   这一条需要基座措辞层面的裁决，且**改基座措辞必须同步维护 mock-llm 的探针字面**（项目记忆已登记）。
   落地：本批（N1）已把 ZA-SYS-04 改为事实边界口径（未覆盖即如实说明未能确认、先给可确认的部分、
   与站点无关的通用请求不受此限），并新增探针字面登记。

## 后果

- **正面**：产品形态与实现口径重新一致；评测维度不再有一个「实现已删除、规则仍要求」的悬空维度；
  默认 E2E 门从基线即红转绿。
- **代价**：知识型 pack 的叙事从「有据讲解 + 拒答边界」变为「有据讲解 + 事实边界」，
  「敢答什么」的边界比拒答模式模糊——这正是 §决策待定项 1 要 Terry 定的东西。
- **已了结**：四条裁决点全部采纳且文本改写已于 N1 批次落地——R8、SSOT §1/§10、UI 规范 §5 与基座
  ZA-SYS-04 均已是事实边界口径，`R8` 与实现相反的状态就此终止。
