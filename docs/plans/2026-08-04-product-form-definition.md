## 1. 定位与差异化

**Zen Agent 是可被用户塑形的浏览器 agent**（类比：浏览器 agent 的 Claude Code / AI 时代的
Tampermonkey）：在任意站点上叠加 agent，按站点/功能动态装配规则、知识、工具面与自动化，
提供功能讲解、UI 引导与受控代执行。

差异化不是单点「可定制」（大厂正在向 skills/custom instructions 收敛，窗口有限），
而是三件套组合——每件大厂各有结构性障碍：

1. **站点级 harness**：pack 承载站点级规则/事实/工具面，而非账号级一段 custom instruction；
2. **可托付的执行治理**：riskTier 分级、HITL、一次性签名、旁路审计，敢碰「动钱动数据」的操作；
3. **中立与所有权**：BYOK 多模型，配置纯数据、本地可导出，不锁在厂商账号里。

竞品两轴分析（定制深度 × 执行治理）显示「harness 级定制 × fail-closed 治理 × 站点知识深度」
的右上角空位当前无人占据；护城河在组合而非单点，最大风险是产品化速度。（依据与来源见竞品调研文档。）

## 2. 概念模型

### 2.1 信任阶梯（四档能力）

| 档 | 能力 | 一句话 | 对应治理 |
|---|---|---|---|
| 看 | 讲解 | 基于 pack 事实的有据回答 | 拒答边界：配置未覆盖明确拒答不编造 |
| 指 | UI 引导 | 页面高亮定位目标元素 | 锚点失配如实降级为文字指引 |
| 做 | 受控代执行 | API 调用协助 | 服务端分级判定、HITL 确认、一次性签名、审计 |
| 托管 | 自动化 | 周期/事件触发的托管任务 | 需确认项收口到人；无人值守禁自动执行不可撤销写操作 |

阶梯是产品叙事资产：用户从零信任到放权托管的渐进路径，对应大厂 ask/act 两档给不了的粒度。
资源配比：讲解与代执行是主线，引导为 pack 可选能力（capability 声明），自动化是付费场景重心。

### 2.2 配置四层

| 层 | 内容 | 谁能改 | 载体 |
|---|---|---|---|
| L0 平台基座 | 安全基座、执行治理（HITL/签名/审计）、riskTier 判定 | 不可改（产品卖点） | 平台代码 + `assets/system-prompt.md` |
| L0 用户侧开关 | 站点授权、模型选择/BYOK、数据披露 | 用户（全局设置） | extension options |
| L1 站点包 pack | 域匹配与 featureId 路由、规则、事实、工具面（riskTier/resultSchema/prepare）、skills、引导锚点、触发器预设 | pack 作者（官方/社区/自建） | `assets/packs/<id>/` 纯数据 |
| L2 个人定制 | 个人规则、个人事实、偏好、对 pack 的收紧（关工具/降档/关触发器）、对话沉淀记忆 | 所有用户（门槛最低） | 待立契约（见 §7 待决 D1） |
| L3 自动化 | 触发条件、绑定任务、风险档、节流 | 用户声明；pack 可提供预设 | adr-018/019 泛化中 |

L1 在 P1（去硬编码）完成后即基本齐备；产品化增量集中在 L2——它是「用户可塑形」第一次被普通用户摸到的地方。

### 2.3 会话模型

会话跟随浏览器**标签组**（adr-012），**可跨站点**；站点/pack 上下文随当前页面动态换装（装配换出），
是会话内的瞬时属性而非会话身份。跨站任务组（adr-013）在此模型上组合多个站点的能力。

### 2.4 配置方式：三入口、一份数据

配置的 SSOT 永远是纯数据文件（继承 adr-007），三种入口都是它的编辑器前端：

1. **文件/导入导出**（已有）：pack 作者与 power user；pack zip 导入导出支撑早期社区分享（GitHub 仓库形式，暂不做 marketplace 产品）。
2. **面板结构化编辑**：普通用户，仅暴露 L2 + L0 开关（规则=文本条目列表、工具收紧=三态矩阵、偏好=表单）；不在面板内做自由 markdown 编辑器，L1 编辑继续走文件。
3. **对话沉淀（teach）**：对话产出规则草稿，经确认卡显式入库（见 R3）。

pack 作者工具长期推迟，以「agent 辅助起草 pack 文件初稿」替代（同时验证远期「pack 自动生成」方向）。

## 3. 形态规则（规范性）

以下规则贯穿所有表面与配置层，是评审沉淀的产品红线。MUST 语义按契约理解；
与架构红线（U1-U7、ZA-C-WHERE-*）重叠处以架构文档为准，本节只陈述产品层表达。

- **R1 单向收紧**：L2/L3 对工具面与 riskTier MUST 只能收紧、不能放宽；放宽的唯一路径是更换/升级 pack（用户显式安装行为）。
- **R2 全层纯数据**：四层配置 MUST 全部为 prompt/markdown/JSON，不含可执行代码——同时满足 CWS 合规、第三方 pack 可审计、可导出迁移。
- **R3 确认写入**：对话内容 MUST NOT 直接修改任何配置；teach 沉淀走「草稿 → 用户显式确认 → 入库」通道（确认卡本质是一次 HITL）。
- **R4 来源可追溯**：任何触发器/规则/收紧项在 UI 上 MUST 可追溯「作用站点 + 来源层」（L1 pack 预置 / L2-L3 用户自建 / 平台模板）；注入透明视图与配置中心可互相印证。
- **R5 会话身份与站点上下文分离**：会话头部 MUST NOT 固定展示站点身份；站点/pack 上下文展示为动态属性（输入框上方上下文条、消息内引用、切换分隔线）。
- **R6 如实呈现**：引导锚点失配、代执行失败、部分完成 MUST 如实告知并降级，不假装成功。
- **R7 无人值守底线**：自动化任务 MUST NOT 自动执行不可撤销的写操作；需确认项收口到人。平台级不可配置。
- **R8 拒答边界**：配置未覆盖的问题 MUST 明确拒答并指引安装对应 pack，不猜测。
- **R9 通用性曲线**：机制层全站点通用；读类自动化（页面监测/提取/汇报）零配置任意站点可用；写类能力 MUST 以已声明的工具面（pack 或自建）为前提——无契约的写操作不放行。

## 5. 能力通用性矩阵

| 站点配置深度 | 讲解 | 引导 | 代执行 | 自动化 |
|---|---|---|---|---|
| 零配置站点（无 pack） | 基于页面上下文的通用讲解 | 无 | 无 | 只读页面监测（平台模板） |
| 知识型 pack（仅 feature.md + facts.md） | 有据讲解 + 拒答边界 | pack 声明锚点则有 | 无 | 只读监测 |
| 深配置 pack（含工具面/触发器） | 完整 | 完整 | 分级代执行 | 读写完整（受 R7） |

知识型 pack 是社区造包的最低门槛（写两个 markdown 即可跑通讲解）——引导锚点与工具面
MUST NOT 成为 pack 准入门槛，这对生态冷启动是关键设计。

## 6. 分期落位（对 P 线的插入建议）

P1（去硬编码）是本文一切「用户可塑形」的硬前提，优先级不变且上升。建议在现有 P 线插入：

- **P2.5 透明性 + L2 个人定制**：注入构成视图、面板 L2 编辑（规则列表/只收紧矩阵/偏好）。放在 P3（CWS 上架）之前——商店叙事依赖差异化第一次可被感知。
- **P3.5 teach + pack 分享**：对话沉淀确认流、pack 导出导入 + 社区目录（GitHub 形式）。
- 远期（P4 后）：pack 自动生成（agent 观察起草、人审生效），依赖 pack 契约成熟。

## 8. 风险与权衡

- **大厂趋同**（现在进行时）：对冲靠三件套中大厂做不了的部分（站点生态、治理深度、中立所有权）；速度是主要变量。
- **定制复杂度吓退主流用户**：默认零配置即好用（P4 托管 + 内置 pack），定制走渐进披露：能看见 → 能改 → 能教 → 能生成；每个定制入口须能回答宗旨基准两问（ZA-C-META-01）。
- **第三方 pack 注入面**：社区 pack 本质是不可信 prompt 进 harness；R1（只收紧）+ R2（纯数据）+ L0 不可覆盖构成防线，pack 分享上线前按 D1/adr-020 复核。
- **引导锚点维护成本**：随 pack 数量线性增长，故引导仅为可选能力且失配必降级（R6），核心承诺不押在锚点上。
