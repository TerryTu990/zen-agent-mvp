# Zen Agent UI/UX 风格规范（v1）

> 状态：v1（2026-08-04）。类型：参考（人读层）。
> 本文是产品 UI/UX 的约束权威，适用于：插件侧边栏、配置中心（options 页）、上手流程、
> HITL/确认类卡片，以及注入宿主页面的引导覆盖层。
> **令牌与视觉语言的 SSOT 是仓库根 `DESIGN.md`（Atelier）**：色值、字族、圆角、动效的取值与语义以它为准；
> 本文 §3 是其在产品表面的落地摘录，两者冲突时先改 DESIGN.md、再同步本文。
> 上游事实：产品形态定义（`../plans/2026-08-04-product-form-definition.md`，形态规则 R1-R9）、
> 12 张定稿设计稿（`product-form-cards/`）、logo（`apps/extension/icons/icon.svg`）。
> 结构参照业界公开设计系统（GitHub Primer、IBM Carbon、Shopify Polaris、DTCG 令牌架构，见文末来源）：
> 原则 → 令牌 → 布局 → 组件 → 内容语气 → 可访问性；组件约束附治理语义映射（Carbon 式逐组件规范）。
> 规范性措辞（MUST/SHOULD/MAY）仅出现在标注「约束」的条目中。

## 1. 设计原则

1. **治理可见（Governance is UI）**：风险档、来源归属、确认流不是装饰而是核心信息，永远显性呈现（R4/R7）。
2. **如实呈现**：失败、降级、部分完成、事实边界如实展示，无成功假象（R6）；空态与错误态是一等公民。
3. **渐进披露**：默认界面零配置可用；定制入口按「能看见 → 能改 → 能教」逐层展开，不把复杂度前置。
4. **克制与谦逊（Zen）**：低饱和、少投影、少动效；注入宿主页面时不喧宾夺主、可随时移除。
5. **语义一致**：同一含义在所有表面用同一颜色、同一术语、同一控件形态（§7 术语表）。

## 2. 品牌与 logo

### 2.1 logo 规格（现行资产）

- 图形：透明底、Z 形折线笔画（viewBox 40，stroke 3.4，圆头圆角转角），起止端各一实心圆点、终点右侧一小灰点；无底砖。
- 色值：Z 笔画 墨黑 `#12161C`，起点 青 `#0E7490`、终点 红 `#B42318`、尾点 灰 `#94A3B8`（与 ZenTest 品牌 mark 同源，几何与配色逐字一致）。源文件 `apps/extension/icons/icon.svg`，派生 16/32/48/128 png（Playwright 栅格化，透明底）。
- 使用约束：MUST 整体等比缩放，MUST NOT 改动笔画粗细、圆角比例或配色；四周留白 ≥ 图形宽 1/8；
  最小可用尺寸 16px（浏览器工具栏）。

### 2.2 品牌色（Atelier 归一后）

产品 UI 强调色 = 黏土橙 `#B4552F`（DESIGN.md `tertiary`），与 logo 同源，v1 的「禅青 `#0f766e`」双轨已作废。
黏土与治理警示色 `--hitl #8F6516` 色相相近，故按用途分离，不靠色相分辨：

- **黏土（约束）**：唯一的交互/强调驱动——主按钮底、焦点环、开关开态、品牌标记、client 模式色。
  MUST NOT 表达任何治理语义（风险档、运行状态、收紧标识、成败）。
- **agent 紫 `#5E5396`（约束）**：专用于 AI/agent 语义（侧边栏头部、发送按钮、server 模式色），
  同样 MUST NOT 表达治理语义。
- 界面中出现品牌标识时用「logo 图形原样 + 衬线文字标」组合（侧边栏头部与配置中心导航品牌区即此形态）。

## 3. 设计令牌

令牌分两层（DTCG 式 primitive → semantic）；**界面代码 MUST 只消费语义层**，原始值只在本表定义处出现。
取值权威是 `DESIGN.md`（Atelier）；下表是它在产品表面的语义命名落地。侧边栏运行在 Shadow DOM 内、
配置中心是独立文档，两处各自内联同名令牌（无法共享一份 `tokens.css`），命名 MUST 与下表一致。

### 3.1 颜色

| 语义令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#F4F3EF` | 页面/面板底色（近中性 off-white，非奶油暖白） |
| `--surface` | `#FBFAF8` | 卡面、气泡、输入控件底；靠与 paper 的明度差分层 |
| `--raised` | `#EDEAE2` | 导航当前项、开关关态轨道等浅层块 |
| `--ink` | `#1C1B18` | 主文字（暖近黑）。正文 MUST NOT 用纯黑 |
| `--ink-2` | `#615C54` | 次级文字、说明、提示与占位 |
| `--muted` | `#8E887D` | 禁用态与非文本装饰；MUST NOT 用于正文（对比不足 4.5:1） |
| `--line` / `--line-strong` | `#E6E2DA` / `#D6D0C4` | 分隔发丝边 / 控件描边 |
| `--clay` | `#B4552F` | 唯一强调：主按钮底、焦点环、开关开态、品牌标记、client 模式色 |
| `--agent` / `--agent-soft` | `#5E5396` / `#ECEAF3` | AI/agent 语义：侧边栏头部、发送按钮、server 模式色 |
| `--auto` / `--auto-bg` | `#3E6B4E` / `#E7EEE8` | 治理语义：自动执行、运行中、成功 |
| `--hitl` / `--hitl-bg` | `#8F6516` / `#F7F0E2` | 治理语义：需确认、已收紧、警示 |
| `--off` / `--off-bg` | `#A23A2C` / `#F5E4E0` | 治理语义：已禁用、失败、不可撤销风险 |

**治理语义色红线（约束）**：auto 绿 / hitl 橙 / off 红三组 MUST 专用于治理语义（风险档、
运行状态、收紧标识、成败），MUST NOT 挪作普通装饰或强调；反向亦然——治理语义 MUST NOT
用品牌色（clay / agent 紫）表达。深色文字令牌与对应浅底组合均满足 WCAG AA（见 §8）。
中性说明条不再有专属蓝组：用 `--surface` 底 + `--line` 描边 + `--ink-2` 字。

### 3.2 字体与字阶

- 三族封顶，CJK 靠系统回退，MUST NOT 外链字体（不打包、不引 Google Fonts）：
  衬线 `Fraunces, "Iowan Old Style", "Songti SC", "Noto Serif SC", Georgia, serif`（页标题与品牌字标）；
  无衬线 `"Hanken Grotesk", "Avenir Next", "PingFang SC", "Noto Sans SC", sans-serif`（正文与控件）；
  等宽 `"Geist Mono", "SFMono-Regular", "Noto Sans Mono", Menlo, monospace`（工具 id、URL、令牌名、时间戳、JSON）。
- 字阶（px/字重）：24/500 衬线页标题 · 15/600 卡片与分区标题 · 14/400 正文 · 13/400–500 标签与控件 ·
  12/400 次级与等宽 · 11/400 徽章 · 10.5/500 等宽 caps（字距 .08em，只作表头与系统小标）。
  约束：MUST 使用本字阶，不新增中间档；正文行高 1.55。
- 约束：MUST NOT 全大写正文；`caps` 只作表头/系统小标这类偶发标签，不满屏铺。

### 3.3 间距、圆角、层高、动效

- 间距：4px 基数网格；常用档 4/8/10/12/14/16/20/24/40。卡内边距 14–20，卡间距 16。
- 圆角：`--radius-sm` 6（按钮/输入/小块）· `--radius` 10（提示条/内层块）· `--radius-lg` 14（卡片）·
  `999`（徽章/chip/开关/悬浮球）。约束：大容器、卡片与主按钮 MUST NOT 用全圆角。
- 层高（约束）：近乎扁平——层级靠 `paper → surface` 明度差与发丝边区分；界面内投影 MUST 不超过
  `0 1px 2px rgba(28,27,24,.06)`（侧边栏抽屉本体与悬浮球例外，取值见 DESIGN.md）。
  MUST NOT 用单边彩色描边条、渐变文字、毛玻璃、霓虹/发光。
- 动效（约束）：过渡 120–300ms，缓动 `cubic-bezier(.16,1,.3,1)`，无 bounce/elastic；只动 `transform`/`opacity`；
  MUST 尊重 `prefers-reduced-motion`；宿主页面覆盖层禁用循环动画（引导光晕脉冲 ≤3 次后静止）。

## 4. 布局

| 表面 | 规格 |
|---|---|
| 侧边栏 | 内容按 380px 基准设计，自适应 320–480；结构自上而下固定为：头部（会话身份）→ 消息流 → 上下文条（当前页面/pack/注入构成入口）→ 输入区。头部 MUST NOT 展示站点身份（R5） |
| 配置中心 | 左侧 236px 固定导航（`position:sticky` 满高；品牌区 = logo 图形 + 衬线字标 + caps 副标，其下四项：站点包/个人定制/自动化/全局设置），当前项 `--raised` 底 + `--ink` 字 600。右侧单列内容区，阅读宽度上限 768px 居中，左右留白 40px。每页自上而下：页标题（24 衬线）+ 一句说明 → 分区卡片（标题 + 帮助文案 + 行式设置项）→ 粘性底部保存栏（主按钮「保存」+ 状态行 + 配置版本）。行式设置项 = 左侧标签与说明、右侧单个控件 |
| 宿主页覆盖层 | 仅两类元素：高亮描边（2px `--clay` + 外圈光晕）与浮标（编号 + 一句话）；MUST NOT 修改宿主样式、拦截宿主交互；随引导结束/页面跳转即清除 |

## 5. 组件规范

以定稿设计稿为形态基准，此处只列约束要点；实现细节见对应卡片源文件。

- **按钮**：主=`--clay` 底 + `--surface` 字；次=`--surface` 底 + `--line-strong` 描边；
  危险=`--surface` 底 + `--off` 字；未开放能力=虚线描边 + `--muted` 字且 `disabled`（不做假跳转）。
  内边距 5px 12px，最小高 30，圆角 6。一个视图区最多一个主按钮。
- **输入与下拉**：`--surface` 底 + `--line-strong` 描边、圆角 6、最小高 30；焦点环 2px `--clay`（offset 2px），
  MUST NOT 移除。
- **徽章**：11px、padding 2px 8px、全圆角；治理徽章用语义配对（前景+浅底同组），来源/类型徽章一律中性
  （靠描边与底色分层，不占用治理色）。措辞见 §7 术语表。
- **会话气泡**：用户=`--ink` 底浅字右对齐；agent=`--surface` 卡描边左对齐；事实边界提示=灰底虚线描边弱化。
  事实边界提示只用于「站点功能事实未能确认」的如实说明（R8）；与站点无关的通用请求直接应答，不走该形态。措辞见 §7 术语表。
- **引用条（cite）**：`--paper` 底 + `--line` 整边（Atelier 禁单边彩色描边条），标注知识来源
  （「依据：<pack> · <条目>」）。
- **HITL 确认卡**：hitl 橙描边 + 浅橙卡头「需要你确认」；MUST 含五要素——工具（含机器名）、
  作用站点与来源 pack（R4）、参数摘要、风险行（红组，标注是否不可撤销）、治理小字
  （一次性签名 · 有效期 · 审计留痕）；按钮=确认（主）+ 拒绝（次）。
- **规则草稿卡（teach）**：`--agent` 描边 + `--agent-soft` 卡头；MUST 含适用范围、规则预览、存放位置、
  「保存/仅本次生效」双选与「对话不直接改配置」小字（R3）。
- **透明视图层（手风琴）**：L0 `--paper` 底加锁「不可修改」；展开层 `--line-strong` 描边；条目缩进对齐。
- **触发器/列表卡**：MUST 按站点分组（组头：站点 + 工具面来源徽章）；每行含来源徽章 +
  类型 + 状态 + 开关（R4）。
- **三态矩阵（权限收紧）**：逐工具一行，列=工具（等宽 id + 描述）· 站点包默认 · 生效档位。
  三档（自动执行/需确认/已禁用）用单选圆点行或三档 select 表达均可；约束：低于站点包基线的档位
  MUST 不可选（`disabled`），比默认更严时 MUST 挂「已收紧」徽章，档位文字 MUST 同时带治理语义色与措辞
  （不靠颜色单独传达）；顶部橙组提示条陈述只收紧口径（R1）。命中目标见 §8。
- **提示条**：中性说明=`--surface` 底 + `--line` 描边 + `--ink-2` 字；橙组=治理边界陈述；
  `--paper` 底 + `--line-strong` 描边=平台底线（R7），MUST 不可关闭。
- **开关**：34×19 全圆角，开=`--clay`，关=`--raised` 轨 + `--line-strong` 描边；全表面同一开态色。

## 6. 图标与插画

- 界面图标：线性、1.5–2px 笔画、单色（继承文字色）；treat emoji 为占位（设计稿现状），
  实现时 SHOULD 替换为一致的线性图标集（候选：Lucide，MIT 许可，风格匹配克制原则）。
- 不使用装饰性插画；空态用一句话 + 可执行入口表达。

## 7. 内容与语气（voice & tone）

- 中文为默认语言；保留业界通用英文术语（pack、BYOK、HITL 首次出现给中文注解）。
- 语气：平实、第一人称谦逊（「我不猜测」）、不过度拟人、不用感叹号营销腔。
- 治理固定术语表（约束：同义表达 MUST 统一为下表措辞，R4 的可追溯依赖措辞一致）：

| 语义 | 固定措辞 |
|---|---|
| 风险三档 | 自动执行 / 需确认 / 已禁用 |
| 收紧 | 已收紧（伴随「pack 默认为 X」标注） |
| 来源层 | 站点包预置 / 用户自建 / 平台通用模板 / 对话沉淀 |
| 会话 | 标签组会话 · 可跨站点 |
| 上下文 | 当前页面：<站点> · <区域> |
| 执行治理 | 一次性签名指令 / 全程审计留痕 / 提交后不可撤销 |
| 平台底线 | 「……——平台底线，不可配置」句式 |
| 事实边界 | 「本站点的功能配置未覆盖这一点，我未能确认」+ 先给出可确认的部分 +（可选）安装对应站点包的指引。**不用于通用问题**——与站点无关的请求直接应答（adr-025 D1） |
| 沉淀 | 「对话不会直接修改你的配置——所有沉淀都需要你确认」 |

- 错误与失败文案（约束）：MUST 陈述事实 + 已做/未做 + 下一步（例：「订单尾号 8830 失败
  （运单号校验不通过），未重试，原始报错已记录」）；MUST NOT 出现 secret/token 原文（ZA-C-SEC-04）。

## 8. 可访问性（约束）

- 对齐 WCAG 2.1 AA：正文对比 ≥4.5:1，大字/图形 ≥3:1（本文令牌的「深前景+浅底」配对均按此校验；
  新增配色 MUST 复验）。
- 颜色 MUST NOT 是唯一信息通道：治理状态同时有文字措辞（§7）；成/败点前有文字。
- 键盘可达：所有交互控件可 Tab 聚焦，焦点环 2px `--clay`（offset 2px）MUST NOT 移除；确认卡默认焦点落在
  「拒绝」而非「确认执行」（防误触放权）。
- 命中目标 ≥24×24px（WCAG 2.2 Target Size）；开关（34×19）与圆点单选的实际热区 MUST 经透明外扩到 ≥24px。
- 徽章类状态信息提供 aria-label（如「风险档：需确认」）。

## 9. 主题

v1 仅浅色主题（定稿口径）。深色主题 deferral 锚点：P3 CWS 上架素材制作时评估；若做，
MUST 经语义令牌层整体换肤（§3 结构已预留），MUST NOT 出现逐组件硬编码色。

## 10. 与其他规范的关系

- 形态规则 R1-R9（产品形态定义 §3）是本文上游：本文 §5 各组件的 MUST 项即其 UI 落点。
- `DESIGN.md`（Atelier）是令牌与视觉语言的 SSOT：§3 的取值、§5 的形态约束均以它为上游，冲突时以它为准。
- `product-form-cards/SHARED-STYLE.md` 是设计稿制作规范，其令牌块早于 Atelier 归一（禅青口径），
  与本文 §3 冲突时一律以本文为准。
- 架构红线不受本文影响：覆盖层零治理判定（ZA-C-WHERE-07）、错误不泄敏（ZA-C-SEC-04）等
  在 UI 层的表达已并入对应条目。
