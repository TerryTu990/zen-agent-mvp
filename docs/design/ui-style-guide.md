# Zen Agent UI/UX 风格规范（v1）

> 状态：v1（2026-08-04）。类型：参考（人读层）。
> 本文是产品 UI/UX 的约束权威，适用于：插件侧边栏、配置中心（options 页）、上手流程、
> HITL/确认类卡片，以及注入宿主页面的引导覆盖层。
> 上游事实：产品形态定义（`../plans/2026-08-04-product-form-definition.md`，形态规则 R1-R9）、
> 12 张定稿设计稿（`product-form-cards/`）、logo（`apps/extension/icons/icon.svg`）。
> 结构参照业界公开设计系统（GitHub Primer、IBM Carbon、Shopify Polaris、DTCG 令牌架构，见文末来源）：
> 原则 → 令牌 → 布局 → 组件 → 内容语气 → 可访问性；组件约束附治理语义映射（Carbon 式逐组件规范）。
> 规范性措辞（MUST/SHOULD/MAY）仅出现在标注「约束」的条目中。

## 1. 设计原则

1. **治理可见（Governance is UI）**：风险档、来源归属、确认流不是装饰而是核心信息，永远显性呈现（R4/R7）。
2. **如实呈现**：失败、降级、部分完成、拒答如实展示，无成功假象（R6/R8）；空态与错误态是一等公民。
3. **渐进披露**：默认界面零配置可用；定制入口按「能看见 → 能改 → 能教」逐层展开，不把复杂度前置。
4. **克制与谦逊（Zen）**：低饱和、少投影、少动效；注入宿主页面时不喧宾夺主、可随时移除。
5. **语义一致**：同一含义在所有表面用同一颜色、同一术语、同一控件形态（§7 术语表）。

## 2. 品牌与 logo

### 2.1 logo 规格（现行资产）

- 图形：圆角方块（圆角比例 26/104 ≈ 25%）+ 无衬线 Z 形折线笔画（stroke 13/120，miter 转角）。
- 色值：底 陶土橙 `#B4552F`，笔画 米白 `#F4F3EF`。源文件 `apps/extension/icons/icon.svg`，派生 16/32/48/128 png。
- 使用约束：MUST 整体等比缩放，MUST NOT 改动笔画粗细、圆角比例或配色；四周留白 ≥ 图形宽 1/8；
  最小可用尺寸 16px（浏览器工具栏）。

### 2.2 品牌色双轨裁决（v1 决定 + 归一锚点）

现状冲突：logo 用陶土橙 `#B4552F`，而定稿 UI 用禅青 `#0f766e`；且陶土橙与警示橙 `#b45309`
色相极近，若进入界面会与 hitl 治理语义混淆。v1 裁决：

- **产品 UI 主色 = 禅青**（12 张定稿设计稿口径）；
- **陶土橙仅限 logo 图形本身**（工具栏图标、商店图标、启动页品牌区），MUST NOT 用于界面控件、
  文字、徽章或任何治理语义；
- 界面中出现品牌标识时用「logo 图形原样 + 禅青文字标」组合（侧边栏头部即此形态：品牌点/logo + Zen Agent 文字）。
- 归一 deferral：P2 品牌回归时裁决 logo 是否重绘为禅青系（倾向重绘，理由：消除与 hitl 橙的语义冲突；
  届时本节随之修订）。→ 已登记为产品形态文档 §7 之外的补充待决 D6，锚点 P2。

## 3. 设计令牌

令牌分两层（DTCG 式 primitive → semantic）；**界面代码 MUST 只消费语义层**，原始值只在本表定义处出现。
单一事实来源：设计稿制作期为 `product-form-cards/SHARED-STYLE.md` 内联 CSS 块；
产品实现时 MUST 落为共享 `tokens.css`（CSS custom properties，命名与下表一致），设计稿与产品同源。

### 3.1 颜色

| 语义令牌 | 值 | 用途 |
|---|---|---|
| `--bg` | `#f4f5f7` | 页面/面板底色 |
| `--surface` | `#ffffff` | 卡面、气泡、输入控件底 |
| `--ink` | `#1a1d21` | 主文字 |
| `--ink-2` | `#4b5563` | 次级文字 |
| `--muted` | `#8a919c` | 辅助/占位/时间戳 |
| `--line` / `--line-strong` | `#e5e7eb` / `#d1d5db` | 分隔线 / 控件描边 |
| `--brand` / `--brand-soft` | `#0f766e` / `#e6f2f1` | 主操作、选中态、引用条 / 主色浅底 |
| `--auto` / `--auto-bg` | `#16803c` / `#e8f5ec` | 治理语义：自动执行、运行中、成功 |
| `--hitl` / `--hitl-bg` | `#b45309` / `#fdf3e3` | 治理语义：需确认、已收紧、警示 |
| `--off` / `--off-bg` | `#b91c1c` / `#fdeaea` | 治理语义：已禁用、失败、不可撤销风险 |
| `--info` / `--info-bg` | `#1d4ed8` / `#eef4fd` | 中性说明条 |

**治理语义色红线（约束）**：auto 绿 / hitl 橙 / off 红三组 MUST 专用于治理语义（风险档、
运行状态、收紧标识、成败），MUST NOT 挪作普通装饰或强调；反向亦然——治理语义 MUST NOT
用品牌色表达。深色文字令牌与对应浅底组合均满足 WCAG AA（见 §8）。

### 3.2 字体与字阶

- 字族：`-apple-system, "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif`；代码/单号用
  `ui-monospace, "SF Mono", Menlo, monospace`。
- 字阶（px/字重）：15/600 面板与页标题 · 13/600 卡片与分区标题 · 13/400 正文 · 12/400 次级 ·
  11/400 徽章与治理小字。约束：MUST 使用本字阶，不新增中间档；行高 1.6。

### 3.3 间距、圆角、层高、动效

- 间距：4px 基数网格；常用档 4/6/8/10/12/14/16/20/24。卡内边距 12–16，卡间距 12。
- 圆角：`--radius` 12（卡片）· `--radius-sm` 8（按钮/输入/提示条）· `999`（徽章/chip/开关）。
- 层高（约束）：投影 MUST 不超过 `0 1px 2px rgba(0,0,0,.04)`；层级优先用描边与底色区分，不靠投影。
- 动效（约束）：过渡 150–200ms ease-out，仅用于展开/高亮/开关；MUST 尊重
  `prefers-reduced-motion`；宿主页面覆盖层禁用循环动画（引导光晕脉冲 ≤3 次后静止）。

## 4. 布局

| 表面 | 规格 |
|---|---|
| 侧边栏 | 内容按 380px 基准设计，自适应 320–480；结构自上而下固定为：头部（会话身份）→ 消息流 → 上下文条（当前页面/pack/注入构成入口）→ 输入区。头部 MUST NOT 展示站点身份（R5） |
| 配置中心 | 内容区基准 960px；左侧 200px 固定导航（站点包/个人定制/自动化/全局设置），当前项 `--brand-soft` 底 + `--brand` 字 |
| 宿主页覆盖层 | 仅两类元素：高亮描边（2px `--brand` + 外圈光晕）与浮标（编号 + 一句话）；MUST NOT 修改宿主样式、拦截宿主交互；随引导结束/页面跳转即清除 |

## 5. 组件规范

以定稿设计稿为形态基准，此处只列约束要点；实现细节见对应卡片源文件。

- **按钮**：主=禅青底白字；次=白底 `--line-strong` 描边；危险=白底红字红边。内边距 6px 14px，
  圆角 8。一个视图区最多一个主按钮。
- **徽章**：11px、padding 2px 8px、全圆角；颜色 MUST 用语义配对（前景+浅底同组）。治理徽章
  措辞见 §7 术语表。
- **会话气泡**：用户=禅青底白字右对齐；agent=白卡描边左对齐；拒答=灰底虚线描边弱化（R8 专用形态）。
- **引用条（cite）**：`--brand` 左边框 3px + `--brand-soft` 底，标注知识来源（「依据：<pack> · <条目>」）。
- **HITL 确认卡**：hitl 橙描边 + 浅橙卡头「需要你确认」；MUST 含五要素——工具（含机器名）、
  作用站点与来源 pack（R4）、参数摘要、风险行（红组，标注是否不可撤销）、治理小字
  （一次性签名 · 有效期 · 审计留痕）；按钮=确认（主）+ 拒绝（次）。
- **规则草稿卡（teach）**：禅青描边 + 浅青卡头；MUST 含适用范围、规则预览、存放位置、
  「保存/仅本次生效」双选与「对话不直接改配置」小字（R3）。
- **透明视图层（手风琴）**：L0 灰底加锁「不可修改」；展开层禅青描边；条目左侧 2px 竖线缩进。
- **触发器/列表卡**：MUST 按站点分组（组头：站点 + 工具面来源徽章）；每行含来源徽章 +
  类型 + 状态 + 开关（R4）。
- **三态矩阵（权限收紧）**：单选圆点行×（自动执行/需确认/禁用）列；比 pack 默认更严的选择挂
  「已收紧」徽章，pack 默认位灰点标注；顶部橙组提示条陈述只收紧口径（R1）。
- **提示条**：蓝组=中性说明；橙组=治理边界陈述；灰底加 🛡 =平台底线（R7），MUST 不可关闭。
- **开关**：34×19 全圆角，开=禅青，关=`--line-strong`。

## 6. 图标与插画

- 界面图标：线性、1.5–2px 笔画、单色（继承文字色）；treat emoji 为占位（设计稿现状），
  实现时 SHOULD 替换为一致的线性图标集（候选：Lucide，MIT 许可，风格匹配克制原则）。
- 不使用装饰性插画；空态用一句话 + 可执行入口表达。

## 7. 内容与语气（voice & tone）

- 中文为默认语言；保留业界通用英文术语（pack、BYOK、HITL 首次出现给中文注解）。
- 语气：平实、第一人称谦逊（「我不猜测」）、不过度拟人、不用感叹号营销腔。
- 治理固定术语表（约束：同义表达 MUST 统一为下表措辞，R4 的可追溯依赖措辞一致）：

| 语义 | 固定措辞 |
|---|---|
| 风险三档 | 自动执行 / 需确认 / 已禁用 |
| 收紧 | 已收紧（伴随「pack 默认为 X」标注） |
| 来源层 | 站点包预置 / 用户自建 / 平台通用模板 / 对话沉淀 |
| 会话 | 标签组会话 · 可跨站点 |
| 上下文 | 当前页面：<站点> · <区域> |
| 执行治理 | 一次性签名指令 / 全程审计留痕 / 提交后不可撤销 |
| 平台底线 | 「……——平台底线，不可配置」句式 |
| 拒答 | 「……不在我的知识范围内，我不猜测」+ 安装指引 |
| 沉淀 | 「对话不会直接修改你的配置——所有沉淀都需要你确认」 |

- 错误与失败文案（约束）：MUST 陈述事实 + 已做/未做 + 下一步（例：「订单尾号 8830 失败
  （运单号校验不通过），未重试，原始报错已记录」）；MUST NOT 出现 secret/token 原文（ZA-C-SEC-04）。

## 8. 可访问性（约束）

- 对齐 WCAG 2.1 AA：正文对比 ≥4.5:1，大字/图形 ≥3:1（本文令牌的「深前景+浅底」配对均按此校验；
  新增配色 MUST 复验）。
- 颜色 MUST NOT 是唯一信息通道：治理状态同时有文字措辞（§7）；成/败点前有文字。
- 键盘可达：所有交互控件可 Tab 聚焦，焦点环 2px `--brand`（offset 2px）；确认卡默认焦点落在
  「拒绝」而非「确认执行」（防误触放权）。
- 命中目标 ≥24×24px（WCAG 2.2 Target Size）；开关/圆点单选实际热区扩展到 24px。
- 徽章类状态信息提供 aria-label（如「风险档：需确认」）。

## 9. 主题

v1 仅浅色主题（定稿口径）。深色主题 deferral 锚点：P3 CWS 上架素材制作时评估；若做，
MUST 经语义令牌层整体换肤（§3 结构已预留），MUST NOT 出现逐组件硬编码色。

## 10. 与其他规范的关系

- 形态规则 R1-R9（产品形态定义 §3）是本文上游：本文 §5 各组件的 MUST 项即其 UI 落点。
- `product-form-cards/SHARED-STYLE.md` 是设计稿制作规范，其令牌块与本文 §3 同源；两者冲突时以本文为准。
- 架构红线不受本文影响：覆盖层零治理判定（ZA-C-WHERE-07）、错误不泄敏（ZA-C-SEC-04）等
  在 UI 层的表达已并入对应条目。
